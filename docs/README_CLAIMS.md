# README claim-to-evidence review

This review checks what the README claims against the distributed source and sanitized historical evidence. It does not independently reproduce the original device investigation, certify all hardware compatibility, or establish a disclosure assessment. No live router command or Windows task registration was performed for this documentation review.

| README claim | Supporting material | Practical limit |
| --- | --- | --- |
| Vendor management CLI reaches Linux UID 0 | [Root-access record](../archive/raw-evidence/LINUX_ACCESS_VERIFIED.json) and [discovery report](../findings/ROOT_ACCESS_VERIFIED.md) | One tested device/build; requires the management credential. |
| Stock Dropbear runs with a public key in a RAM-backed chroot | [Canonical setup](../scripts/phase6a_setup.sh), [live setup report](../archive/phase-history/PHASE6A_RESULTS.md), [scheduled-service proof](../archive/raw-evidence/PHASE9_SCHEDULED_RESTORE.json) | Six private bind targets and a read-only original JFFS2 root; real UID 0, not a security sandbox. |
| Host identity is pinned before Telnet credentials and for custom SSH | [Router connection](../automation/src/dlink_ssh_restore/router.py), [SSH handshake/verification](../automation/src/dlink_ssh_restore/ssh.py), [restore tests](../automation/tests/test_restore.py), [SSH integration tests](../automation/tests/test_ssh_integration.py) | Telnet remains plaintext; preliminary SSH verification does not authenticate that separate transport. |
| Repeated restore avoids duplicate provisioning; rollback is scoped | [State orchestration](../automation/src/dlink_ssh_restore/restore.py), [rollback implementation](../automation/src/dlink_ssh_restore/rollback.py), [restore tests](../automation/tests/test_restore.py), [rollback tests](../automation/tests/test_rollback.py) | Cleanup can refuse unknown ownership, changed identity, or unsafe state. It is not guaranteed cleanup under every failure. |
| Restore, repeat, and rollback worked before and after restart | [Pre-restart trial](../archive/raw-evidence/PHASE9_MANUAL_PRE_RESTART.json), [post-restart trial](../archive/raw-evidence/PHASE9_MANUAL_POST_RESTART.json), [trust verification](../archive/raw-evidence/PHASE9_POST_RESTART_KEY_VERIFICATION.json), [explicit trust update](../archive/raw-evidence/PHASE9_POST_RESTART_TRUST_UPDATE.json) | Owner-performed restart; changed key needed verification/acceptance. Fully unattended key rotation is not implemented. |
| An optional Windows scheduled monitor was deployed and verified | [Task installer](../automation/windows/install-task.ps1), [task record](../archive/raw-evidence/PHASE9_TASK_DEPLOYMENT.json), [independent SSH proof](../archive/raw-evidence/PHASE9_SCHEDULED_RESTORE.json) | Running monitor and live SSH were checked. Startup, logon, and network-event triggers were not individually forced through reboot/sign-out/disruption. Interactive user token is required. |
| The apparent PTY failure was caused by client stdin handling | [Controlled PTY diagnosis](SSH_PTY_DIAGNOSTICS.md), [execution record](../archive/raw-evidence/PHASE6B_EXECUTION.json) | Holding stdin open worked with the same daemon/mounts. The underlying Windows handle failure was not instrumented; no claim about every PTY problem. |
| Python 3.12+ and Windows-specific credential storage | [Package metadata](../automation/pyproject.toml), [credential backend](../automation/src/dlink_ssh_restore/credentials.py) | Windows 11 is the documented target, not a source-enforced Windows version minimum. Some offline tests can run elsewhere. |
| Firmware extraction reproduces the original artifact set | [Recovered extractor and instructions](../research/firmware/README.md), [validation record](../research/firmware/EXTRACTION_VALIDATION.json), [offline tests](../tests/test_firmware_extractor.py) | Only the exact size/digest-verified image is supported. All 3,627 outputs matched retained private bytes; those reference bytes and literal credentials are not distributed. Extraction is not a fresh live-login test. |
| Normal tests are offline; real-device test is opt-in | [Live-test gate](../automation/tests/test_router_integration.py), [offline test guide](../automation/README.md#offline-and-authorized-live-tests) | Local SSH integration and task-definition checks are not live-router reproduction. |

The source and records support the README's device-specific outcome. They do not support wider D-Link compatibility, automatic credential recovery by the restoration tool, autonomous router startup persistence, verified end-to-end WAN isolation, every scheduler trigger working, or completed vendor notification. The README makes none of those claims.
