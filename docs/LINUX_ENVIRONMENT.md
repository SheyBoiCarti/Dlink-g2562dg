### Filesystems and capacities

| Mount / path | Actual backing and state | Persistence implications |
|---|---|---|
| `/` | `mtd:rootfs`, JFFS2, **ro**, 40960 KiB total, 24724 used, 16236 available | Free space is not writable at present. A separate `rootfs rw` listing is the kernel rootfs entry; the mounted JFFS2 root is read-only |
| `/data` | `/dev/mtdblock7`, JFFS2, **rw**, 2048 KiB total, 576 used, 1472 available | Persistent flash candidate, but vendor log storage; no write or reboot-survival test performed |
| `/tmp` | tmpfs, configured size limit 512 MiB | RAM-backed. Limit exceeds available physical RAM and is not guaranteed allocatable capacity |
| `/var` | Symlink `/tmp/var` | Volatile, recreated at boot |
| `/mnt` | tmpfs, 52656 KiB configured capacity | Not an attached persistent disk |
| `/dev`, `/dev/pts` | tmpfs/devtmpfs and devpts | Runtime device state |
| `/overlay` | Empty directory; no overlay mount observed | Do not apply normal OpenWrt overlay/extroot assumptions |

`/proc/partitions` listed MTD block devices only; no active `sda` storage was observed. `/etc/config/fstab` contains a **disabled** ext4 `/dev/sda1` mount at `/home`, not an implemented SSH persistence mechanism.

Important links: `/etc/passwd -> /var/passwd`, `/etc/group -> /var/group`, `/etc/hosts -> /var/hosts`, `/etc/resolv.conf -> /var/resolv.conf`, `/etc/fstab -> /tmp/fstab`, and `/etc/mtab -> /proc/mounts`. Account edits would target RAM and be regenerated by startup; none were made. `/etc/shadow` is a separate read-only-rootfs file. Only account status classifications were retained, never its values.

### Init and available tools

Live `/etc/inittab` starts `/etc/rc.d/rcS`, which calls `/usr/syscfg/sys.init.sh`. That script regenerates Unix account files and launches `tdsmgr`. Live `tdsmgr` contains the invocation `sh /usr/syscfg/sys.init_after.sh`; the script starts `sysmgr`, `srvcmgr`, `utils` and web/other services. This combines live script observations with static strings, not a traced/reboot-tested event timeline.

There is no `/etc/init.d/dropbear`, `/etc/config/dropbear`, `/etc/default/dropbear` or `/etc/rc.local` in the inspected live environment. Existing `/etc/init.d/telnet` references OpenWrt infrastructure that is not the observed active vendor launch path. Do not invoke it to manage the live console.

`awk`, `readlink`, `base64`, `tar`, `dd`, `md5sum`, `strings`, `ip`, `iptables`, `ip6tables`, `netstat`, `dropbear`, `dropbearkey` and `opkg` exist. `opkg` was not invoked. No `unshare`/`nsenter` command or NAND-aware dump utility was established. Package presence does not establish feed/ABI compatibility; no packages were installed.

The running kernel command line includes `console=ttyAMA1,115200`, while live inittab respawns `/bin/sh` on `ttyAMA0`. These are distinct software settings; they neither identify external UART pads nor establish electrical voltage. No hardware interaction occurred.
